## 0. 設計主軸
- **一句話主軸**：給羽蕎（國中會考生）在手機和電腦上練參考書的題目。要有精緻、專注的感覺。最重要的是**首頁選好科目、按「開始練習」就能做題；做完當場看對錯和詳解，答錯的題在結算頁一鍵再練**（v1.4 起不做錯題本、收藏夾）。
- **每屏主角**：

| 畫面 | 主角（唯一） | 主動作（唯一） | 要降級的元素 |
|---|---|---|---|
| 1 登入 | 登入按鈕 | 用 Google 登入 | 說明文字 |
| 2 首頁／題庫 | 主操作列（科目／匯入校對／開始練習）＋這次要練卡 | 開始練習 | 書卡清單 |
| 3 作答 | 題目與四個選項 | 選答案 → 下一題 | 泡泡列、頂部列 |
| 4 結算 | 分數＋本回單元表 | 再練錯的 N 題 | 從頭再做、回首頁 |
| 7 匯入校對 | 紅標題目的預覽＋編輯 | 確認 → 存入 | 批次資訊 |

- **作答端基底（宗良已確認，2026-11-02）**：
  - **沿用 JEV 測驗**（https://tony197653.github.io/bot/jev-quiz/ ，UX 報告在 `/workspace/ux-jev/`）的版面骨架和作答流程：一題一頁、當場對錯、頂部對錯泡泡、再練錯題、支援鍵盤。
  - **視覺不沿用 JEV**：風格定稿時由 BD 套用元件庫，重做選項按壓、對錯揭曉、換題轉場和結算頁。
  - **TU 的 Canvas**（「羽蕎・會考數學與理化診斷小測驗」）只參考兩件事：題庫格式，以及交卷結果的資訊結構（v1.2 起不做單元強弱表）。
- **參考模板**：待 BD 指定（作答骨架以 JEV 為準）。

- **風格定稿**：**待 BD 提供**。想要的感覺：待定，宗良一貫偏好精緻高級感。元件編號見第 8 節。
- **不要清單**：
  - 不要把題目或圖片放進 GitHub repo（repo 是公開的）。
  - 不要用 localStorage 當主要紀錄。
  - 不要用免費 AI。

## 1. 功能範圍
- **要解決的問題**：羽蕎的參考書題目只能寫在紙上，寫完要自己對答案，也看不出哪個單元弱，錯的題目很少回頭再練。
- **目標**：
  1. 宗良拍照，家教TU 轉成題目，宗良校對後存進題庫。
  2. 羽蕎在手機或電腦作答，兩邊的紀錄是同一份。
  3. 結算頁可以「再練錯的 N 題」（v1.4 起不做錯題本、收藏夾；v1.4.1 起不做複製摘要）。
- **這一版要做（v1）**：
  1. Google 登入＋email 允許名單（D3）。
  2. 題庫瀏覽：書 → 單元 → 回。
  3. 兩種範圍：
     - 整回。
     - 單元練習：從該單元所有回的題目隨機抽 10 題，不到 10 題就全部出。
  4. 兩種對答案方式（D2）：當場對（預設）、交卷才對（模考）。
  5. 只有單選題，可以有題組（D6）、圖、KaTeX 公式。
  6. 結算頁（本回單元表、錯題清單、再練錯的 N 題）；首頁主操作列「科目／匯入校對／開始練習」（v1.4，學生只有科目和開始練習）。
  8. 匯入校對頁（只有管理者能用）：選檔 → 紅標檢查 → 預覽和編輯 → 存入（D7）。
  9. 「回報題目有誤」（D8）：作答時可以回報，管理者在匯入頁的「回報」分頁修正已存入的題目。
- **這一版不做（之後再說）**：
  - 多選、填充、計算題。
  - 網頁內裁圖工具（v1 只能上傳新圖替換）。
  - 限時模考（v1 只顯示用時）。
  - 家長看板、多位學生。
  - 單元強弱表、跨回合的總摘要（v1.2 取消）。

## 2. 流程
**主流程（羽蕎）**：
1. 登入。
2. 首頁用「科目」下拉篩選，點某一回或某單元（不點就是今日建議）。
3. 在「這次要練」卡選對答案方式和是否打亂（會記住上次），按「開始練習」。
4. 作答。
5. 交卷，看結算。
6. 「再練錯的 N 題」，或回首頁。

**主流程（宗良＋TU）**：
1. 宗良拍題目頁和詳解頁，傳給 TU。
2. TU 照 `photo-to-json-guide.md` 產出批次 JSON，傳給宗良。
3. 宗良打開匯入頁選檔，處理紅標，按「確認」。
4. 存入。題目 status=checked 之後，羽蕎就看得到。

```
[登入] → [首頁/題庫]（科目｜匯入校對｜開始練習）→ [作答] ⇄（跳題）
              │                                         ↓ 交卷／最後一題
              └→ [匯入校對]（只有管理者看得到）         [結算] → 再練錯的 N 題 → [作答]
                                                               → 回首頁
舊網址 #/mine、#/wrong、#/fav、#/units → 導回 [首頁]
```

**分支**：
- **第一次進來**：首頁沒有作答紀錄，今日建議改成「從第一本書的第 1 回開始」。
- **題庫是空的**：顯示 E1 空狀態（學生：「題目還在準備中」＋「重新整理」；管理者：「去匯入校對」），「開始練習」停用並在 E1 寫原因。
- **不在名單**：登出，並顯示該 email 和白話說明「這個帳號（xxx@gmail.com）還沒加入名單，請宗良把它加進去，或換一個帳號登入」，下面放「換一個帳號登入」（B1，叫出 Google 帳號選擇）。不留在沒有按鈕的畫面。
- **LINE 等內建瀏覽器**：不顯示登入按鈕，改成提示「請用 Safari／Chrome 開啟」，並提供「複製網址」按鈕。
- **中途離開再回來**：作答進度存在本機（localStorage，鍵見 §5.4）。首頁的今日建議顯示「繼續第 3 回（7/20）」。換了裝置就看不到這份進度。
- **離開作答頁**：要確認（「離開的話這回還沒交卷，進度會留在這台裝置」）。
- **結算寫入失敗**：結果先放進本機待傳佇列，顯示「還沒存到雲端，重試」。下次載入時自動重傳。
- **返回上一步**：作答中按返回鍵等同「離開」；結算頁按返回回到首頁（不回作答頁）；匯入頁按返回回到首頁（草稿已自動存）。
- **沒有死路的網址**（紅線 3）：
  - 舊網址（v1.4）：`#/mine`、`#/mine?src=…`、`#/wrong`、`#/fav`、`#/units` 一律用 `location.replace('#/')` 導回首頁，不跳提示（網站還沒上線，沒有人用過這些網址），按返回也不會再回到舊網址。
  - 不認得的 hash：E1「找不到這一頁」＋「回首頁」（B1）。
  - 重新整理或直接打開 `#/result`，記憶體裡沒有結果：E1「這回的結果已經存好了」＋「回首頁」（B1）。有待傳佇列時加一行「還沒存到雲端，重試」（同結算頁）。
  - 重新整理 `#/quiz`：有本機進度就接著做；沒有就 E1「目前沒有進行中的作答」＋「回首頁」（B1）。
  - 學生打開 `#/import`：E1「這一頁只有管理者能用」＋「回首頁」（B1）。
- **作答或校對中登入過期、或帳號被移出名單**（紅線 4、11）：不中斷、不跳頁、不清掉畫面。交卷寫入被拒時，結果放進待傳佇列，顯示「登入已經過期，結果先留在這台裝置。請按『重新登入』，登入後會自動補存」＋「重新登入」（B1）。匯入頁存入被拒時同樣保留草稿。
- **不自動跳轉**（紅線 4）：當場對揭曉後不自動跳下一題；除了「登入成功 → 首頁」和使用者自己按的按鈕，任何時候都不自動換頁、刷新或關視窗。新版部署後也不強制重新整理。

## 6. 資料架構
### 6.1 Firestore 集合（D4、D5）
| 集合／文件 | 欄位 | 誰能讀／寫 | 重新整理後 |
|---|---|---|---|
| `allow/{email}` | `role`（"admin"／"student"）、`name` | 讀：本人（email 相符）和管理者。寫：只能在 Console 手動加 | 保留 |
| `banks/{bookId}` | `title, subject, grade, edition, units:[{unitCode, name, rounds:[{round, label, count}]}], updatedAt` | 讀：名單內。寫：管理者 | 保留 |
| `questions/{id}` | schema 的 question 全部欄位＋`bookId, round, roundKey`（"bookId\|unitCode\|round"）、`importBatch, updatedAt`；存入時 `review.status` 一律是 "checked"（草稿不進雲端） | 讀：名單內只能讀 status=="checked" 的題，管理者全部能讀。寫：管理者 | 保留 |
| `groups/{groupId}` | schema 的 group 全部欄位＋`bookId, updatedAt` | 讀：名單內。寫：管理者 | 保留 |
| `users/{uid}/attempts/{attemptId}`（v1.4：id 由前端產生，見下方結算寫入） | `scope{type:"round"\|"unit"\|"retry", bookId?, unitCode?, round?}, mode:"instant"\|"exam", qids[], answers[]（-1＝未答）, correct, total, score, byUnit{ "M9-2": {unit, subject, correct, total}, … }, startedAt, endedAt, at` | 本人（admin 也一樣，可以作答、存自己的紀錄）；只能新增，不能改或刪 | 保留 |
| `reports/{qid}__{uid}`（同一人同一題只有一份） | `qid, uid, reason:"answer"\|"typo"\|"figure"\|"other", note（≤200 字）, status:"open"\|"done", at` | 名單內可以新增（status 一定是 open）；只有管理者能讀和改成 done | 保留 |

- **大小**：一題含圖的文件最多約 150 KB×（圖的數量）。一題最多 4 張圖，加起來仍遠低於 1 MiB 上限。
- **讀取次數**：
  - 一回約 20～40 次。
  - 每日免費額度 5 萬次，兩個帳號用都綽綽有餘。
- **查詢**：
  - 一回：`where roundKey == X && review.status == "checked"`。只有等式條件，不需要複合索引。
  - 單元：`where bookId == X && unitCode == Y && review.status == "checked"`。
  - 首頁「已做 N 次・最高分」：每個工作階段讀一次 `attempts`（`orderBy at desc, limit 200`），在前端彙總。這也是單欄索引。
  - `firestore.indexes.json` 寫 `{"indexes": [], "fieldOverrides": []}`。
  - `attempts.byUnit` 仍然保留：結算頁本回單元表要用（v1.2 不再做 30 天加總；v1.4.1 拿掉本回摘要）。
  - 回報分頁：`reports` 用 `where status == "open"` 查詢（單欄）。
- **結算寫入**（v1.4）：只寫一筆 attempt，不再用 transaction（qstats 已拿掉）。交卷時前端先產生 `attemptId`（`crypto.randomUUID()`），存進本機待傳佇列，再 `setDoc(users/{uid}/attempts/{attemptId}, …)`；`byUnit` 由前端依這回每題的 unitCode 算好，跟 `startQuiz` 回傳的 `byUnit` 同一份資料。重送時用同一個 id：文件已經存在時規則會當成「更新」而拒絕，前端看到這筆已存在就當作成功、移出佇列，所以不會變兩筆（firebase-record-sync）。
- **存入題庫**：先讀 `banks/{bookId}`，在前端把這批的單元和回合併進 `units`（同一個 unitCode 同一回就覆蓋 count），再用 writeBatch 一起寫入題、題組和 banks，每批最多 400 筆。存入時 `review.status` 寫 "checked"、`checkedBy`、`checkedAt`。沒確認的題不寫進去（留在本機草稿，IndexedDB `quizbank-v1`／`importDraft`，見 §5.4）。

### 6.2 安全規則重點
規則寫在 `firebase/firestore.rules`，照 stay-quiz 的 `valid()` 寫法：用 `hasOnly`／`hasAll` 檢查欄位，時間要等於 `request.time`，最後一條全部拒絕。
```
function signedIn() { return request.auth != null && request.auth.token.email_verified == true; }
function allowed()  { return signedIn() && exists(/databases/$(database)/documents/allow/$(request.auth.token.email)); }
function admin()    { return allowed() && get(/databases/$(database)/documents/allow/$(request.auth.token.email)).data.role == "admin"; }
match /allow/{email}       { allow read: if signedIn() && (request.auth.token.email == email || admin()); allow write: if false; }
match /banks/{id}          { allow read: if allowed(); allow write: if admin(); }
match /groups/{id}         { allow read: if allowed(); allow write: if admin(); }
match /questions/{id}      { allow read: if admin() || (allowed() && resource.data.review.status == "checked"); allow write: if admin(); }
match /users/{uid}/attempts/{a} { allow read: if allowed() && request.auth.uid == uid;
                                  allow create: if allowed() && request.auth.uid == uid && validAttempt(request.resource.data);
                                  allow update, delete: if false; }
match /reports/{r}  { allow create: if allowed() && request.resource.data.uid == request.auth.uid && r == request.resource.data.qid + "__" + request.auth.uid && validReport(request.resource.data);
                     allow read: if admin();
                     allow update: if admin() && request.resource.data.diff(resource.data).affectedKeys().hasOnly(['status']) && request.resource.data.status == "done";
                     allow delete: if false; }
match /{path=**} { allow read, write: if false; }
```
- `validAttempt`：
  - 欄位只能是 `scope, mode, qids, answers, correct, total, score, byUnit, startedAt, endedAt, at`（`hasOnly`），而且 `byUnit` 一定要有（`hasAll`）。
  - `d.qids.size() == d.total && d.answers.size() == d.total && d.total <= 200`（規則語言不能連寫等號，要拆開）。
  - `0 ≤ correct ≤ total`。
  - `at == request.time`。
  - `d.byUnit is map && d.byUnit.size() >= 1 && d.byUnit.size() <= 50`。各單元 correct／total 的合計是否等於 correct／total，規則語言沒辦法檢查，由前端保證，並列入規則測試的說明。
- `validReport`：
  - 文件 id 固定是 `qid__uid`，已經存在就變成更新，學生沒有更新權限，所以同一題不能重複回報。
  - 欄位只能是 `qid, uid, reason, note, status, at`（`hasOnly`）。
  - `reason in ["answer","typo","figure","other"]`、`note.size() <= 200`、`status == "open"`、`at == request.time`。
- **admin 也能作答**：`allowed()` 對 admin 和 student 都成立，`users/{uid}/…` 只看 uid 是不是本人，所以宗良用自己的帳號作答、存紀錄都沒問題。驗收第 18 項會測。
- **v1.4 拿掉的路徑**：`users/{uid}/qstats`、`users/{uid}/favorites` 不寫規則，由最後一條 `match /{path=**}` 全部拒絕；網站還沒部署，沒有舊資料要清。

## 10. 羽蕎測驗模板（之後所有測驗共用的標準，宗良 2026-11-02 指定）
本案順便訂下「羽蕎測驗模板」。之後幫羽蕎做的任何測驗（參考書題庫、診斷小測驗、各科練習），都從這個模板開始，不再各做一套。

**(1) 題庫 JSON 格式就是共用標準**
- 標準格式就是 `schema.json`（schemaVersion 1），欄位說明和範例都寫在檔案裡。
- 家教TU 以後出題（不論是照片轉題目，還是自己出的練習題），一律輸出這個格式，並用 `tools/validate_batch.py` 自我檢查。
- 不是從參考書來的題目，`source.bookId` 用一個代表出題來源的代碼（例：`tu-diag`＝TU 診斷題、`tu-practice`＝TU 練習題），`page` 填 1，`answerPage` 填 null。
- 要改格式時，必須：
  - 升 `schemaVersion`；
  - 在 skill 草稿（見 (4)）的版本紀錄寫上舊版怎麼轉成新版；
  - 經宗良同意。
- 舊的 Canvas 題目照 `photo-to-json-guide.md` 附錄轉成這個格式。

**(2) 作答端和結算頁是可以重複套用的頁面**
- 作答（第 3 畫面）和結算（第 4 畫面）寫成獨立的模組。題目來源只透過一個介面取得，不直接寫死 Firestore 查詢：
  ```
  startQuiz({ title, questions, groups, mode: "instant"|"exam", shuffle, onFinish(result) })
  // v1.4 拿掉 v1.2 的 favorite 參數（不做收藏）
  // questions／groups 就是 schema.json 的 question／group 物件
  // result = { qids, answers, correct, total, score, startedAt, endedAt, byUnit:[{unitCode, unit, correct, total}] }
  ```
- 本案用 Firestore 提供題目。別的測驗也可以直接從靜態 JSON 檔給題目（不需要登入、不存紀錄），用同一套作答和結算畫面。
- 模組不可以出現書名、科目、「羽蕎」這類寫死的字。標題這類文字從參數傳入。
- 檔案：`quiz-bank/js/quiz.js`（作答）、`quiz-bank/js/result.js`（結算）、`quiz-bank/js/render.js`（題目、公式、圖）、`quiz-bank/css/quiz.css`（作答和結算的樣式，跟其他頁的樣式分開）。
- 另外做一個最小示範頁 `quiz-bank/template-demo.html`：讀 `test-data/fake-batch.json`，直接開始作答。之後要開新測驗，就複製這一頁。

**(3) 結案時由美學總監BD 收進模板庫**
- 結案（closeout）時由 BD 把作答端和結算頁收進宗良的模板庫，跟 `template-index` 一起管理：
  - 給一個模板代碼（建議 Q 系列的新編號，由 BD 決定）；
  - 寫上品味標籤和截圖（390、1280）；
  - 寫明來源路徑（`quiz-bank/template-demo.html`＋上面四個檔案）。
- 之後宗良說「照羽蕎測驗模板做」或指定那個代碼時，PL 和 PM 就用這一套。
- PL 不直接改 template-index，交給 BD 處理。
