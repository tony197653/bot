## 0. 設計主軸
- **一句話主軸**：給羽蕎（國中會考生）在手機和電腦上練參考書的題目。要有精緻、專注的感覺。最重要的是**錯的題目會自動回來再練，想再看的題目隨手收藏、之後集中練**。
- **每屏主角**：

| 畫面 | 主角（唯一） | 主動作（唯一） | 要降級的元素 |
|---|---|---|---|
| 1 登入 | 登入按鈕 | 用 Google 登入 | 說明文字 |
| 2 首頁／題庫 | 今日建議＋書卡 | 開始作答 | 篩選列 |
| 3 作答 | 題目與四個選項 | 選答案 → 下一題 | 泡泡列、頂部列 |
| 4 結算 | 分數＋本回單元表 | 再練錯的 N 題 | 複製摘要、回首頁 |
| 5 錯題本 | 錯題清單 | 練這 N 題 | 篩選 |
| 6 收藏夾 | 收藏題清單（依科目→單元分組） | 練習收藏題 | 科目篩選、收藏日期 |
| 7 匯入校對 | 紅標題目的預覽＋編輯 | 確認 → 存入 | 批次資訊 |

- **作答端基底（宗良已確認，2026-11-02）**：
  - **沿用 JEV 測驗**（https://tony197653.github.io/bot/jev-quiz/ ，UX 報告在 `/workspace/ux-jev/`）的版面骨架和作答流程：一題一頁、當場對錯、頂部對錯泡泡、再練錯題、支援鍵盤。
  - **視覺不沿用 JEV**：風格定稿時由 BD 套用元件庫，重做選項按壓、對錯揭曉、換題轉場和結算頁。
  - **TU 的 Canvas**（「羽蕎・會考數學與理化診斷小測驗」）只參考兩件事：題庫格式，以及交卷結果的資訊結構（v1.2 起不做單元強弱表）。

  - 不要把題目或圖片放進 GitHub repo（repo 是公開的）。
  - 不要用 localStorage 當主要紀錄。
  - 不要用免費 AI。

## 1. 功能範圍
- **要解決的問題**：羽蕎的參考書題目只能寫在紙上，寫完要自己對答案，也看不出哪個單元弱，錯的題目很少回頭再練。
- **目標**：
  1. 宗良拍照，家教TU 轉成題目，宗良校對後存進題庫。
  2. 羽蕎在手機或電腦作答，兩邊的紀錄是同一份。
  3. 自動整理錯題本；解題時可以手動收藏題目，之後在收藏夾集中練；結算頁可以一鍵複製本回摘要給家教TU。
- **這一版要做（v1）**：
  1. Google 登入＋email 允許名單（D3）。
  2. 題庫瀏覽：書 → 單元 → 回。
  3. 四種範圍：
     - 整回。
     - 單元練習：從該單元所有回的題目隨機抽 10 題，不到 10 題就全部出。
     - 錯題本：一次最多 10 題，最久沒練的先出。
     - 收藏練習（v1.2）：從收藏夾目前的篩選範圍隨機抽最多 10 題。
  4. 兩種對答案方式（D2）：當場對（預設）、交卷才對（模考）。
  5. 只有單選題，可以有題組（D6）、圖、KaTeX 公式。
  6. 結算頁、錯題本（連對 2 次移出＋手動移出，D9）、收藏夾（解題時點星號收藏，上限 500 題，§5.7）。
  7. 「複製給家教TU」摘要（D10，結算頁的本回摘要）。
  8. 匯入校對頁（只有管理者能用）：選檔 → 紅標檢查 → 預覽和編輯 → 存入（D7）。
  9. 「回報題目有誤」（D8）：作答時可以回報，管理者在匯入頁的「回報」分頁修正已存入的題目。
- **這一版不做（之後再說）**：
  - 多選、填充、計算題。
  - 網頁內裁圖工具（v1 只能上傳新圖替換）。
  - 限時模考（v1 只顯示用時）。
  - 家長看板、多位學生。
  - 單元強弱表、跨回合的總摘要（v1.2 取消）。
  - 收藏分資料夾、收藏加筆記（v1 只有一個收藏夾）。
  - 間隔重複排程、列印、離線 PWA。
  - 作答到一半的進度同步（v1 只存在本機，見 §5.4）。
- **不能動的地方**：
  - 匯入格式的核心欄位跟 Canvas 相容（見 `schema.json` 開頭說明）。
  - 作答骨架照 JEV（宗良已確認）。
  - 題庫 JSON 格式是「羽蕎測驗模板」的共用標準（第 10 節），要改格式必須升 schemaVersion。

## 2. 流程
**主流程（羽蕎）**：
1. 登入。
2. 首頁選一回，或選「今日建議」。
3. 開始設定：選對答案方式和是否打亂。
4. 作答。
5. 交卷，看結算。
6. 「再練錯的 N 題」，或回首頁。

**主流程（宗良＋TU）**：
1. 宗良拍題目頁和詳解頁，傳給 TU。
2. TU 照 `photo-to-json-guide.md` 產出批次 JSON，傳給宗良。
3. 宗良打開匯入頁選檔，處理紅標，按「確認」。
4. 存入。題目 status=checked 之後，羽蕎就看得到。

```
[登入] → [首頁/題庫] → [開始設定] → [作答] ⇄（跳題）
              │                         ↓ 交卷／最後一題
              ├→ [錯題本] → 練錯題 ──→ [作答]
              ├→ [收藏夾] → 練習收藏題 → [作答]
              └→ [匯入校對]（管理者）
[作答] 任何一題都可以點右上角 ☆ 收藏／取消
[結算] → 再練錯的 N 題 → [作答]
       → 回首頁
       → 回收藏夾（只有收藏練習的結算才有）
```

**分支**：
- **第一次進來**：首頁沒有作答紀錄，今日建議改成「從第一本書的第 1 回開始」。
- **題庫是空的**：顯示 E1 空狀態（學生：「題目準備中」；管理者：「去匯入」）。
- **不在名單**：登出，並顯示該 email 和白話說明「這個帳號（xxx@gmail.com）還沒加入名單，請宗良把它加進去，或換一個帳號登入」，下面放「換一個帳號登入」（B1，叫出 Google 帳號選擇）。不留在沒有按鈕的畫面。
- **LINE 等內建瀏覽器**：不顯示登入按鈕，改成提示「請用 Safari／Chrome 開啟」，並提供「複製網址」按鈕。
- **中途離開再回來**：作答進度存在本機（localStorage，鍵見 §5.4）。首頁的今日建議顯示「繼續第 3 回（7/20）」。換了裝置就看不到這份進度。
- **離開作答頁**：要確認（「離開的話這回還沒交卷，進度會留在這台裝置」）。
- **結算寫入失敗**：結果先放進本機待傳佇列，顯示「還沒存到雲端，重試」。下次載入時自動重傳。
- **返回上一步**：作答中按返回鍵等同「離開」；結算頁按返回回到首頁（不回作答頁）；收藏練習的結算頁按返回回到收藏夾。
- **收藏寫入失敗**：星號先切換，寫入失敗再退回原狀並跳 N1 提示（文字見 §4.4），不打斷作答。
- **收藏夾已滿 500 題**：點空心星不收藏，跳 N1「收藏夾已滿 500 題，先整理一些再收藏」＋「前往收藏夾」；作答中按「前往收藏夾」要先經過「離開」確認。
- **沒有死路的網址**（紅線 3）：
  - 不認得的 hash：E1「找不到這一頁」＋「回首頁」（B1）。
  - 重新整理或直接打開 `#/result`，記憶體裡沒有結果：E1「這回的結果已經存好了」＋「回首頁」（B1）、「看錯題本」（B2）。有待傳佇列時加一行「還沒存到雲端，重試」（同結算頁）。
  - 重新整理 `#/quiz`：有本機進度就接著做；沒有就 E1「目前沒有進行中的作答」＋「回首頁」（B1）。
  - 學生打開 `#/import`：E1「這一頁只有管理者能用」＋「回首頁」（B1）。
- **作答或校對中登入過期、或帳號被移出名單**（紅線 4、11）：不中斷、不跳頁、不清掉畫面。交卷寫入被拒時，結果放進待傳佇列，顯示「登入已經過期，結果先留在這台裝置。請按『重新登入』，登入後會自動補存」＋「重新登入」（B1）。匯入頁存入被拒時同樣保留草稿。
- **不自動跳轉**（紅線 4）：當場對揭曉後不自動跳下一題；除了「登入成功 → 首頁」和使用者自己按的按鈕，任何時候都不自動換頁、刷新或關視窗。新版部署後也不強制重新整理。

### 4.3 動畫
選項按壓、對錯揭曉、換題轉場、結算頁的動效**由 BD 在風格定稿時提供**（照 `animation-timeline-spec`）。基本規則：
- 按壓用 `scale(.97)`。
- hover 只寫在 `@media (hover:hover) and (pointer:fine)` 裡。
- 遵守 `prefers-reduced-motion`。
- 焦點環用 `--halo`。
- **對錯不只靠顏色**（紅線 6）：泡泡答對加 ✓、答錯加 ✗、未答只有題號、目前這題加外框；選項揭曉時正解旁寫「正確答案」、選錯的寫「你的答案」。

## 5. 規則
### 5.1 計分
- 每題 1 分。分數＝答對題數÷總題數×100，四捨五入到整數。未答算錯。
- 題組的每個小題各算 1 題。
- 再練錯題、錯題本的回合也照樣計分，attempts 會記下 scope。

### 5.2 錯題本（D9）
寫入 qstats 時，每題依這次的結果更新：
- **答錯或未答**：`wrong+1`、`streak=0`、`inWrongBook=true`、`manualOut=false`（手動移出的題，再錯就重新加入）。
- **答對**：`streak+1`。如果 `inWrongBook` 而且 `streak≥2`，就改成 `inWrongBook=false`（自動移出）。
- **手動移出**：`inWrongBook=false`、`manualOut=true`。
- 所有範圍（整回、單元、錯題本）的作答都會更新。
- 錯題卡上的「連對 1/2」就是 `min(streak,2)/2`。

### 5.3 結算頁本回單元表三色
v1.2 起**沒有單元強弱表**，原本的 30 天統計全部刪除（被 2026-11-02 21:45 決定取代）。這裡只留結算頁「本回單元表」用的門檻：
- 資料來源：這一回的 `byUnit`（每個單元的答對數÷題數）。

| 狀態 | 條件 | 標籤（L2） |
|---|---|---|
| 掌握 | 正確率 ≥85% | 成功色 |
| 部分掌握 | 60%～84% | 警告色 |
| 需加強 | <60% | 危險色 |

- 用詞沿用 Canvas。顏色由 BD 定。顏色以外一定要有文字。
- 本回該單元少於 3 題就加「題數少」L3 標籤。

### 5.4 進度暫存（只存在本機）
- 鍵：`quizbank:v1:progress:{uid}`。內容：`{scope, mode, qids, answers, idx, startedAt}`。
- 交卷寫入成功後清掉。
- localStorage 不能用時改存在記憶體（重新整理就沒了）。
- 待傳佇列鍵：`quizbank:v1:pending:{uid}`。
- **匯入草稿**（紅線 11）：存在 IndexedDB（資料庫 `quizbank-v1`、store `importDraft`），不用 localStorage（含圖的一批可能超過 localStorage 約 5 MB 的上限）。內容是整批題目、編輯過的欄位、換過的圖、「我看過了」和確認狀態；每次編輯停頓 1 秒自動存。存入成功的題目才從草稿移除。IndexedDB 不能用時顯示 §4.4 的提示，並提醒「先把確認好的題存入，不要關掉這頁」。

### 5.5 匯入紅標條件
`tools/validate_batch.py` 和匯入頁用**同一套規則**。PM 要在 JS 裡實作同樣的檢查，並用 `schema.json` 裡的範例做對照測試。

| 代碼 | 條件 | 範圍 |
|---|---|---|
| COUNT_MISMATCH | `questions` 筆數 ≠ `batch.expectedCount` | 整批（橫幅） |
| EXPLAIN_MISSING | `explain` 是空字串 | 題 |
| EXPLAIN_MISMATCH | `id`／`matchKey` 跟 `source` 對不上，或 TU 標了這個代碼 | 題 |
| ANSWER_MISSING | TU 標了這個代碼（schema 已經要求 answer 0–3） | 題 |
| OPTION_COUNT | TU 標了這個代碼（v1 不收這種題） | 題 |
| FORMULA_CHECK | `\(` 和 `\)` 數量不同，或匯入頁 KaTeX 渲染丟出錯誤 | 題 |
| FIGURE_MISSING | 題幹或題組題幹有「如圖／下圖／右圖／附圖／圖（／如表／下表…」，卻沒有圖；或圖解碼後小於 200 bytes | 題 |
| LOW_CONFIDENCE | `extract.confidence < 0.8` | 題 |
| DUPLICATE_ID | 同批 id 重複 → 紅標；跟題庫已有的 id 相同 → 改標「將覆蓋」（L3），不算紅標 | 題 |
| GROUP_BROKEN | 題目的 groupId 找不到，或題組的 questionIds 指到不存在的題 | 題／整批 |
| IMAGE_TOO_BIG | 單張圖解碼後 >150 KB | 題 |

- **有紅標的題**：要先修好（修改後會重新檢查），或對每個紅標按「我看過了」，才能按「這題確認」。
- **`extract.uncertain`**：在 F 區用黃底逐條列出，不擋確認（黃底旁加「待確認」文字，不只靠顏色）。
- **畫面上的紅標名稱**（紅線 13；代碼只用小字附在後面）：COUNT_MISMATCH「題數對不上：這批應該有 N 題，實際 M 題，請 TU 檢查有沒有漏題」；EXPLAIN_MISSING「缺少詳解」；EXPLAIN_MISMATCH「詳解可能對錯題，請對照詳解頁」；ANSWER_MISSING「缺少答案，請在下面選正確答案」；OPTION_COUNT「選項不是 4 個，v1 不收這種題，請刪題」；FORMULA_CHECK「公式顯示不出來，請檢查括號」；FIGURE_MISSING「題目說『如圖』但沒有圖，請換圖」；LOW_CONFIDENCE「TU 不太確定，請對照照片」；DUPLICATE_ID「題號重複」；GROUP_BROKEN「題組對不上」；IMAGE_TOO_BIG「圖太大，請重新上傳」。

### 5.7 收藏夾（v1.2，取代單元強弱表）
業界做法：Quizlet 的星號、Anki 的 flag、作業幫和題庫類 App 的收藏，都是「一顆星號、手動加減、跟錯題分開、可以只練收藏」。本案照這個預設。
- **只由使用者手動加減**：解題時點星號收藏或取消；收藏夾頁可以取消。
- **跟錯題本互相獨立**：錯題本照 §5.2 自動加入、連對 2 次移出；收藏不看對錯。同一題可以同時在錯題本和收藏夾；收藏題答對**不會**自動移除；從錯題本移出也不影響收藏。
- **上限 500 題**（前端用記憶體裡的收藏清單計數，第 501 題不收並提示）。
- **排序與分組**：依科目 → 單元（unitCode 排序）分組；組內最新收藏的在上（`addedAt` 由新到舊）。
- **收藏練習**：從目前篩選範圍隨機抽最多 10 題；當場對、打亂順序；計分、寫入 qstats（會照 §5.2 影響錯題本）和 attempts 都跟其他範圍一樣，`scope.type = "fav"`。
- **作答中的狀態**：進站讀一次收藏清單（最多 500 筆小文件）放在記憶體，作答畫面依此顯示空心或實心；收藏或取消後同步更新記憶體和首頁數量。
- **刪掉的題目**：收藏指到已刪除或讀不到的題，就不顯示，並在背景刪掉那筆收藏。

## 6. 資料架構
### 6.1 Firestore 集合（D4、D5）
| 集合／文件 | 欄位 | 誰能讀／寫 | 重新整理後 |
|---|---|---|---|
| `allow/{email}` | `role`（"admin"／"student"）、`name` | 讀：本人（email 相符）和管理者。寫：只能在 Console 手動加 | 保留 |
| `banks/{bookId}` | `title, subject, grade, edition, units:[{unitCode, name, rounds:[{round, label, count}]}], updatedAt` | 讀：名單內。寫：管理者 | 保留 |
| `questions/{id}` | schema 的 question 全部欄位＋`bookId, round, roundKey`（"bookId\|unitCode\|round"）、`importBatch, updatedAt`；存入時 `review.status` 一律是 "checked"（草稿不進雲端） | 讀：名單內只能讀 status=="checked" 的題，管理者全部能讀。寫：管理者 | 保留 |
| `groups/{groupId}` | schema 的 group 全部欄位＋`bookId, updatedAt` | 讀：名單內。寫：管理者 | 保留 |
| `users/{uid}/attempts/{autoId}` | `scope{type:"round"\|"unit"\|"wrong"\|"retry"\|"fav", bookId?, unitCode?, round?}, mode:"instant"\|"exam", qids[], answers[]（-1＝未答）, correct, total, score, byUnit{ "M9-2": {unit, subject, correct, total}, … }, startedAt, endedAt, at` | 本人（admin 也一樣，可以作答、存自己的紀錄）；只能新增，不能改或刪 | 保留 |
| `users/{uid}/qstats/{qid}` | `unitCode, subject, tries, correct, wrong, streak, inWrongBook, manualOut, lastAnswer, lastAt` | 本人；新增或更新，不能刪 | 保留 |
| `users/{uid}/favorites/{qid}`（v1.2） | `bookId, subject, unitCode, addedAt` | 只有本人能讀、新增、刪除；不能改（取消後再收藏就是新的一筆） | 保留 |
| `reports/{qid}__{uid}`（同一人同一題只有一份） | `qid, uid, reason:"answer"\|"typo"\|"figure"\|"other", note（≤200 字）, status:"open"\|"done", at` | 名單內可以新增（status 一定是 open）；只有管理者能讀和改成 done | 保留 |

- **大小**：一題含圖的文件最多約 150 KB×（圖的數量）。一題最多 4 張圖，加起來仍遠低於 1 MiB 上限。
- **讀取次數**：
  - 一回約 20～40 次。
  - 收藏夾：進站讀一次 `favorites`（最多 500 筆），打開收藏夾時再依 qid 讀題目（每 30 個一組）。同一個工作階段只讀一次，之後在記憶體更新。
  - 錯題本：只讀 `inWrongBook == true` 的 qstats（幾十筆），再依 qid 讀題目。
  - 每日免費額度 5 萬次，兩個帳號用都綽綽有餘。
- **查詢**：
  - 一回：`where roundKey == X && review.status == "checked"`。只有等式條件，不需要複合索引。
  - 單元：`where bookId == X && unitCode == Y && review.status == "checked"`。
  - 錯題本：qstats 裡 `inWrongBook == true` 的 qid，每 30 個一組用 `where(documentId(), 'in', ids) && review.status == "checked"` 查詢。**一定要帶 status 條件**，否則學生的查詢會整個被規則拒絕。
  - 收藏夾：`users/{uid}/favorites` 用 `orderBy("addedAt", "desc")`（單欄索引）；題目照錯題本的方法，每 30 個 qid 一組用 `where(documentId(), 'in', ids) && review.status == "checked"`。
  - 首頁「已做 N 次・最高分」：每個工作階段讀一次 `attempts`（`orderBy at desc, limit 200`），在前端彙總。這也是單欄索引。
  - `firestore.indexes.json` 寫 `{"indexes": [], "fieldOverrides": []}`。
  - `attempts.byUnit` 仍然保留：結算頁本回單元表和本回摘要要用（v1.2 不再做 30 天加總）。
  - 錯題本照用 qstats。
  - 回報分頁：`reports` 用 `where status == "open"` 查詢（單欄）。
- **結算寫入**：用一個 transaction，先讀這回所有 qid 的 qstats，依 §5.2 算出新值，再寫入 qstats 和一筆 attempt（`byUnit` 由前端依這回每題的 unitCode 算好，跟 `startQuiz` 回傳的 `byUnit` 同一份資料）。被拒或衝突時重讀再算（firebase-record-sync）。
- **收藏寫入**：點星號就單筆 `setDoc(favorites/{qid}, {bookId, subject, unitCode, addedAt: serverTimestamp()})` 或 `deleteDoc`；不放進結算 transaction。失敗處理跟錯題本、結算一致：先改畫面，失敗退回並提示（§4.4）；離線時不排進待傳佇列（收藏是當下的操作，失敗就請使用者再點）。
- **存入題庫**：先讀 `banks/{bookId}`，在前端把這批的單元和回合併進 `units`（同一個 unitCode 同一回就覆蓋 count），再用 writeBatch 一起寫入題、題組和 banks，每批最多 400 筆。存入時 `review.status` 寫 "checked"、`checkedBy`、`checkedAt`。沒確認的題不寫進去（留在本機草稿，IndexedDB `quizbank-v1`／`importDraft`，見 §5.4）。

### 6.2 安全規則重點
規則寫在 `firebase/firestore.rules`，照 stay-quiz 的 `valid()` 寫法：用 `hasOnly`／`hasAll` 檢查欄位，時間要等於 `request.time`，最後一條全部拒絕。
```
function signedIn() { return request.auth != null && request.auth.token.email_verified == true; }
function allowed()  { return signedIn() && exists(/databases/$(database)/documents/allow/$(request.auth.token.email)); }
function admin()    { return allowed() && get(/databases/$(database)/documents/allow/$(request.auth.token.email)).data.role == "admin"; }
match /allow/{email}       { allow read: if signedIn() && (request.auth.token.email == email || admin()); allow write: if false; }
match /banks/{id}          { allow read: if allowed(); allow write: if admin(); }
match /groups/{id}         { allow read: if allowed(); allow write: if admin(); }
match /questions/{id}      { allow read: if admin() || (allowed() && resource.data.review.status == "checked"); allow write: if admin(); }
match /users/{uid}/attempts/{a} { allow read: if allowed() && request.auth.uid == uid;
                                  allow create: if allowed() && request.auth.uid == uid && validAttempt(request.resource.data);
                                  allow update, delete: if false; }
match /users/{uid}/qstats/{q}   { allow read: if allowed() && request.auth.uid == uid;
                                  allow create: if allowed() && request.auth.uid == uid && validStat(request.resource.data) && request.resource.data.tries == 1;
                                  allow update: if allowed() && request.auth.uid == uid && validStat(request.resource.data)
                                                && ( ( request.resource.data.tries == resource.data.tries + 1
                                                       && request.resource.data.correct - resource.data.correct in [0, 1] )
                                                     || manualOutOnly() );
                                  allow delete: if false; }
match /users/{uid}/favorites/{q} { allow read: if allowed() && request.auth.uid == uid;
                                  allow create: if allowed() && request.auth.uid == uid && validFav(request.resource.data);
                                  allow delete: if allowed() && request.auth.uid == uid;
                                  allow update: if false; }
match /reports/{r}  { allow create: if allowed() && request.resource.data.uid == request.auth.uid && r == request.resource.data.qid + "__" + request.auth.uid && validReport(request.resource.data);
                     allow read: if admin();
                     allow update: if admin() && request.resource.data.diff(resource.data).affectedKeys().hasOnly(['status']) && request.resource.data.status == "done";
                     allow delete: if false; }
match /{path=**} { allow read, write: if false; }
```
- `validStat`：
  - 欄位只能是上表那些（`hasOnly`）。
  - `streak ≤ tries`、`correct + wrong == tries`。
  - `lastAt == request.time`。
- `manualOutOnly()`：
  - 只改了 `inWrongBook`（變成 false）、`manualOut`（變成 true）和 `lastAt`。
  - 寫法：`request.resource.data.diff(resource.data).affectedKeys().hasOnly(['inWrongBook','manualOut','lastAt']) && request.resource.data.inWrongBook == false && request.resource.data.manualOut == true`。
- `validAttempt`：
  - 欄位只能是 `scope, mode, qids, answers, correct, total, score, byUnit, startedAt, endedAt, at`（`hasOnly`），而且 `byUnit` 一定要有（`hasAll`）。
  - `d.qids.size() == d.total && d.answers.size() == d.total && d.total <= 200`（規則語言不能連寫等號，要拆開）。
  - `0 ≤ correct ≤ total`。
  - `at == request.time`。
  - `d.byUnit is map && d.byUnit.size() >= 1 && d.byUnit.size() <= 50`。各單元 correct／total 的合計是否等於 correct／total，規則語言沒辦法檢查，由前端保證，並列入規則測試的說明。
- `validFav`（v1.2）：
  - 欄位只能是 `bookId, subject, unitCode, addedAt`（`hasOnly` 加 `hasAll`）。
  - `bookId`、`subject`、`unitCode` 都是字串，長度 1～40；`addedAt == request.time`。
  - 500 題上限規則語言沒辦法計數，由前端保證，列入規則測試的說明。
- `validReport`：
  - 文件 id 固定是 `qid__uid`，已經存在就變成更新，學生沒有更新權限，所以同一題不能重複回報。
  - 欄位只能是 `qid, uid, reason, note, status, at`（`hasOnly`）。
  - `reason in ["answer","typo","figure","other"]`、`note.size() <= 200`、`status == "open"`、`at == request.time`。
- **admin 也能作答**：`allowed()` 對 admin 和 student 都成立，`users/{uid}/…` 只看 uid 是不是本人，所以宗良用自己的帳號作答、存紀錄、看錯題本和收藏夾都沒問題。驗收第 18 項會測。

## 7. 技術方向
- **架構與部署**：純靜態網頁，不需要建置。放在 `bot` repo 的 `/quiz-bank/`，用 GitHub Pages 發佈（D11）。單頁加 hash 路由：`#/`、`#/quiz`、`#/result`、`#/wrong`、`#/fav`（v1.2 取代 `#/units`；舊網址 `#/units` 導到 `#/fav`）、`#/import`。
- **函式庫**（版本都固定）：
  - Firebase JS SDK 10.14.1，模組化，從 gstatic CDN 載入：app、auth、firestore。
  - KaTeX 0.16.11（jsdelivr）＋ auto-render ＋ mhchem。分隔符號用 `\( \)` 和 `\[ \]`。
  - 不用其他框架。
- **Firebase 專案**：
  - 新開一個專案，用 Spark 免費方案。
  - Firestore 地區 asia-east1。
  - Auth 只開 Google 登入。
  - Authorized domains 加上 `tony197653.github.io`。
  - 不用 Storage（2026-02-03 起要 Blaze 方案），所以圖片用 base64 存在 Firestore（D5）。
  - Web config 寫在前端沒關係，安全靠規則。
- **firebase-record-sync 的要求**：
  - 雲端資料是唯一真相，localStorage 只當快取。
  - CDN 載入 8 秒逾時，加上 `setLogLevel('silent')`。
  - `?emulator=1` 只在 localhost 上有效。
  - 測試在沒合併的分支上做，只用假題目，絕不碰正式資料。
- **版權**：
  - 題目資料只存在 Firestore，repo 裡只有程式和假題目。
  - TU 的批次檔只放在 box 的 `/workspace/quiz-bank-import/`。
- **限制**：
  - 支援 iOS Safari 16 以上、Android Chrome、桌機 Chrome、Edge。
  - 觸控目標至少 44×44px（看起來比較小的元件，例如泡泡，用透明點擊區補到 44）。
  - 文字對比符合 WCAG AA（正文 4.5:1，大字 3:1），BD 定稿時附數值。
  - 手機正文（題幹、選項、詳解、說明文字、錯誤訊息）至少 16px、行高至少 1.5；輸入框字級 16px 以上（iOS 才不會放大畫面）。
  - 字體照 BD 的定稿（羽蕎的頁面用共用的字體 skill「極限銳利字體比較器」）。
- **效能預算**：
  - 首屏 2.5 秒內（4G）。
  - 一回的題目一次載入。圖片用 `loading="lazy"`、`decoding="async"`。
  - 換題不重新讀取 Firestore。

## 10. 羽蕎測驗模板（之後所有測驗共用的標準，宗良 2026-11-02 指定）
本案順便訂下「羽蕎測驗模板」。之後幫羽蕎做的任何測驗（參考書題庫、診斷小測驗、各科練習），都從這個模板開始，不再各做一套。

**(1) 題庫 JSON 格式就是共用標準**
- 標準格式就是 `schema.json`（schemaVersion 1），欄位說明和範例都寫在檔案裡。
- 家教TU 以後出題（不論是照片轉題目，還是自己出的練習題），一律輸出這個格式，並用 `tools/validate_batch.py` 自我檢查。
- 不是從參考書來的題目，`source.bookId` 用一個代表出題來源的代碼（例：`tu-diag`＝TU 診斷題、`tu-practice`＝TU 練習題），`page` 填 1，`answerPage` 填 null。
- 要改格式時，必須：
  - 升 `schemaVersion`；
  - 在 skill 草稿（見 (4)）的版本紀錄寫上舊版怎麼轉成新版；
  - 經宗良同意。
- 舊的 Canvas 題目照 `photo-to-json-guide.md` 附錄轉成這個格式。

**(2) 作答端和結算頁是可以重複套用的頁面**
- 作答（第 3 畫面）和結算（第 4 畫面）寫成獨立的模組。題目來源只透過一個介面取得，不直接寫死 Firestore 查詢：
  ```
  startQuiz({ title, questions, groups, mode: "instant"|"exam", shuffle, onFinish(result), favorite? })
  // favorite（v1.2，選填）= { isOn(qid) → bool, toggle(qid) → Promise<bool> }；不傳就不顯示星號（示範頁）
  // questions／groups 就是 schema.json 的 question／group 物件
  // result = { qids, answers, correct, total, score, startedAt, endedAt, byUnit:[{unitCode, unit, correct, total}] }
  ```
- 本案用 Firestore 提供題目。別的測驗也可以直接從靜態 JSON 檔給題目（不需要登入、不存紀錄），用同一套作答和結算畫面。
- 模組不可以出現書名、科目、「羽蕎」這類寫死的字。標題、摘要開頭這些文字從參數傳入。
- 檔案：`quiz-bank/js/quiz.js`（作答）、`quiz-bank/js/result.js`（結算）、`quiz-bank/js/render.js`（題目、公式、圖）、`quiz-bank/css/quiz.css`（作答和結算的樣式，跟其他頁的樣式分開）。
- 另外做一個最小示範頁 `quiz-bank/template-demo.html`：讀 `test-data/fake-batch.json`，直接開始作答。之後要開新測驗，就複製這一頁。

**(3) 結案時由美學總監BD 收進模板庫**
- 結案（closeout）時由 BD 把作答端和結算頁收進宗良的模板庫，跟 `template-index` 一起管理：
  - 給一個模板代碼（建議 Q 系列的新編號，由 BD 決定）；
  - 寫上品味標籤和截圖（390、1280）；
  - 寫明來源路徑（`quiz-bank/template-demo.html`＋上面四個檔案）。
- 之後宗良說「照羽蕎測驗模板做」或指定那個代碼時，PL 和 PM 就用這一套。
- PL 不直接改 template-index，交給 BD 處理。

**(4) 定稿的 schema 要放一份到共用位置**
- 建議寫成一個 skill，草稿放在 `/workspace/quiz-import-plan/skill-draft.md`（本次已寫好）。內容包括：
  - 什麼時候用；
  - schema 摘要和完整檔案位置；
  - 出題規則；
  - 檢查工具；
  - 模板頁面怎麼套用；
  - 版本紀錄。
- **先不要寫進 workflows**。等宗良看過草稿，結案時再由 skill-authoring 流程正式建立。
- 正式建立時，要把 `schema.json` 和 `tools/validate_batch.py`、`tools/crop_figure.py` 一起複製到 skill 的資料夾，讓 TU 和其他 agent 都讀同一份。
